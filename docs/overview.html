研究ノート · 次元削減

MADR から ScaleRank へ

2020年に始めたマルチエージェント型の次元削減（MADR）を見直し、比較の物差しを作り直したうえで、「守るスケールを指定できる順位保存」という新しい手法 ScaleRank を試作しました。その経緯と結果、見つかった問題を図で説明します。

2026年10月26日時点 コード: github.com/tsjshg/madr（ブランチ proto/scalerank）

要約

何をしたか

過去の試みを読み直し、8データ × 8手法を同じ指標で比べるベンチマーク基盤 drbench を作った。

何が分かったか

既存手法には「局所に強い」か「大域に強い」かのトレードオフがあり、全スケールで勝つ手法はない。

新手法

ScaleRank は守りたいスケールを 1 つのノブ γ で指定する。8データすべてで、局所と大域の両面で既存手法に負けない点を作れた。

残る課題

局所だけなら t-SNE がまだ上。散布図に外れ点が出る。原因は高次元の「anti-hub」で、緩和策は入れたが解決していない。

背景

これまでの経緯

過去の評価

2022年の結果をどう読むか

2022年の最終結果では、MADR は Q スコアで他手法に大差をつけていました。ところが同じノートブックで、近い順位（k=5）だけに絞った局所スコアを見ると順位がほぼ逆転します。

理由は Q スコアの定義にあります。Q スコアは「各点から見た他の全点の順位」が元の空間と埋め込みでどれだけずれたかの合計です。遠い順位のずれも近い順位のずれと同じ重さで数えるので、実質的には大域構造の指標になります。その指標を直接最適化すれば、その指標で勝つのは当然です。

教訓: 評価に使う指標を最適化対象にすると、その指標では必ず良く見える。新しい手法を作る前に、どの指標で何を測るかを固定しておく必要がある。

中心になる指標 RNX(K)

各点について「元の空間での K 近傍」と「2次元での K 近傍」がどれだけ重なるかを測り、ランダム配置なら 0、完全に一致すれば 1 になるよう補正したものです。K を 1 から N まで動かすと、局所（小さい K）から大域（大きい K）までの保存度を1本の曲線で見られます。

既存手法

既存手法の成績

RNX(K) 曲線を見ると、既存手法の得意なスケールがはっきり分かれます。t-SNE は小さい K で最も高く、K が 50 を超えたあたりで MDS や PCA に逆転されます。

8 データ全体で見ても、局所指標と大域指標で1位の手法が入れ替わります。下の表で指標を切り替えると、局所では t-SNE、大域では MDS / PCA が強いことが分かります。

新手法

ScaleRank の考え方

既存手法は「どのスケールを守るか」を内部に暗黙に持っています。ScaleRank はそれをユーザーが指定する分布 p(K) として外に出し、その分布で重み付けした近傍保存を直接最適化します。

1つの三つ組で考える

点 i と近傍サイズ K を決めると、元の空間で i の上位 K 近傍に入る点 j と、入らない点 m があります。2次元で j が m より i の近くにあれば正解です。K を p(K) から引き、j と m を引き、間違っていれば i と j を近づけ、i と m を遠ざけます。

ノブは γ 1つ

p(K) を K−γ に比例させると、γ=1 では小さい K に重みが集まり（局所寄り、AUC_RNX と同じ重み）、γ=0 では全 K が同じ重み（大域寄り）になります。スライダーで γ を動かすと、どのスケールに力を割くかが変わります。

三つ組の重みは p(K) から導けます。j と m の元の順位をそれぞれ r(j)、r(m) とすると、その三つ組は r(j) ≤ K < r(m) を満たす全てのスケール K で効くので、重みはその範囲の p(K) の和になります。距離から経験的に重みを決める TriMap との違いはここです。

試作

試作でつまずいたこと

最適化の失敗ではなく、代理指標の偏り

最初の版は γ=1 でも局所指標が t-SNE に届きませんでした（digits の RNX@10 が 0.44 対 0.58）。そこで、既存手法の埋め込みを ScaleRank 自身の目的関数で採点しました。もし t-SNE の方が低い値なら最適化がうまくいっていないことになります。

原因は目的関数の作りでした。三つ組の正誤は「遠くの非近傍が少し順位を間違える」ことも同じ重さで数えますが、RNX(K) が気にするのは2次元の上位 K に入り込んでくる点だけです。そこで一部の三つ組で、m を「いま2次元で i の近くにいるが、本当は近傍でない点」から選ぶようにしました（hard negative）。

もう1つのバグ. 導入直後、hard negative の割合を 0.3 / 0.6 / 0.9 と変えても結果が完全に同じでした。調べると、順位表を書き込む処理が NumPy のコピーに書き込んでいて、順位表が全部 0 のままでした。hard negative は一度も使われていなかったことになります。修正後に上の改善が出ました。

結果

結果: 局所と大域の両立

8 データ × 3 seed で、γ = 1 / 0.5 / 0 の ScaleRank を既存7手法と比べました。縦軸に局所（RNX@10）、横軸に大域（距離相関）をとると、ScaleRank の3点（赤い線）は8データすべてで、両方の軸で上回る既存手法がない位置にあります。

散布図で見ると違いが分かります。t-SNE はクラスタをきれいに分けますが、クラスタ同士の位置関係は保ちません。MDS は位置関係を保ちますがクラスタが重なります。ScaleRank はその中間で、クラスタを分けつつ配置も保とうとします。ただしクラスタのまわりに点が散るのが目立ちます。これが次の章の主題です。

調査 1

外れ点の正体

2次元での 10-NN 半径が中央値の 3 倍を超える点を「外れ点」と定義して数えると、ScaleRank は t-SNE よりはるかに多く出ていました。

2 種類の外れ点

外れ点の元の空間での様子を調べると、2 種類に分かれました。

  • Pollen の外れ点は元の空間でも孤立していました（10-NN 半径が中央値の 3.9 倍）。これはある程度忠実です。
  • 階層クラスタ（hier_blobs）の外れ点は元の空間では普通の密度でした（1.06 倍）。手法が作った人工物です。

犯人は hard negative と「anti-hub」

hard negative を切ると、hier_blobs の外れ点は 23% から 2% に減りました（最適化手法を変えても変わりません）。さらに、外れる点には共通点がありました。他のどの点の近傍リストにもほとんど入らない点、いわゆる anti-hub です。高次元のデータでは、一部の点が多くの点の近傍になり（hub）、逆にほとんど誰の近傍にもならない点（anti-hub）が大量に生まれます。これを hubness と呼びます。

どんな力が働いているか

学習中に各点が受ける力を、勾配の項ごとに分解し、「自分のクラスタの中心から外向き」の成分を測りました（hier_blobs、エポック 700）。

外れ点への正味の力は内向きですが、他の点より弱い（−0.013 対 −0.038）。学習の後半にクラスタの芯が縮んでいく（中心からの距離 3.5 → 0.6）中で、押し出されるというより取り残されています。近傍関係が非対称なことが根本原因で、t-SNE は点ごとの帯域幅（perplexity の較正）でこれを打ち消しています。

試した対策

対策結果
最適化手法の変更（点ごと Adam / 共有 Adam / SGD）変化なし
hard positive（遠くにいる本当の近傍を優先して引く）どのデータでも悪化
hard negative を順位で重み付け（trustworthiness と同じ形）変化なし
片側 hard negative（入り込んだ点 m は動かさない）わずかに減るだけ（23.8% → 20.4%）
hard negative を学習中に減衰させるblob では減るが、digits の改善を失う
全 K で局所スケーリングした順位を使う外れ点は消えるが、Pollen の距離相関が 0.86 → −0.02 に崩れる
小さい K（≤30）だけ局所スケーリング外れ点が減り、局所・大域もほぼ維持。オプションとして採用

局所スケーリングは、距離を各点の 10 番目の近傍までの距離 σ で割り（d / √(σiσj)）、hubness を弱める標準的な方法です。8 データで比べると、緩和にはなるものの、t-SNE の水準（1% 未満）には届きません。

調査 2

blob で t-SNE に負ける理由

局所指標の差が大きかったのは、高次元ガウス分布でできた2つの合成データです（hier_blobs で 0.24 対 0.34、density_blobs で 0.31 対 0.41）。目的関数を K≈10 に集中させた版（帯域プロファイル）で、t-SNE と同じ土俵にそろえて調べました。

  • hier_blobs: hard negative があると、ScaleRank は自分の目的関数で t-SNE に負けます。hard negative が目的関数そのものを歪めているということです。外すと t-SNE にほぼ並び、目的関数でも上回りました。
  • density_blobs: 目的関数では t-SNE を上回っているのに、RNX@10 では負けています。目的関数と評価指標のずれがまだ残っています。
  • スケールの配分: γ=1 は設計上、K>10 にも多くの重みを割きます（図6）。digits では K=10 に集中させると RNX@10 が 0.599 になり、t-SNE（0.583）を上回りました。局所差の一部は「どのスケールを守るか」という選択の結果です。

hard negative のジレンマ. digits のような多様体的なデータでは必須（RNX@10 が 0.44 → 0.54）ですが、hubness の強い高次元データでは外れ点を作り、目的関数を歪めます。2 次元ではどうしても避けられない「入り込み」まで押し返していることが本質です。

まとめ

割り引いて読むべき点と次の一手

割り引いて読むべき点

  • 局所指標だけなら、t-SNE が全データで1位のまま。
  • AUC_RNX は γ=1 の目的関数に近いものを測っているので、そこでの優位は割り引く必要がある（2022年の Q スコアと同じ構図）。RNX@10 と距離相関は直接は最適化していない。
  • ハイパーパラメータは digits と Pollen だけで調整した。
  • NumPy の試作なので、1回 1.5〜12 秒（t-SNE の 2〜6 倍）。メモリは N² の順位表を持つため、N は 1 万程度まで。

次の一手の候補

  • 目的関数を直接直す. hard negative の代わりに、上位 K の境界にだけ効く重みで precision@K に近い形にする。データ依存のノブを減らせる可能性がある。
  • 正例側の非対称性を直す. t-SNE のように点ごとの帯域で「近傍として引かれる量」をならし、anti-hub にも十分な引力を与える。
  • 大きいデータへ. N² の順位表をやめ、MNIST 10k 規模で回せるようにする。

再現方法

リポジトリ tsjshg/madr の proto/scalerank ブランチで、次のコマンドで再現できます。元データの pickle は親フォルダにある前提です。

uv sync
uv run python scripts/convert_legacy.py      # 2020年の pickle → data/raw/*.npz
uv run drbench run                           # 既存手法（8データ × 3 seed）
uv run drbench run -m scalerank:gamma=1.0 scalerank:gamma=0.5 scalerank:gamma=0.0
uv run drbench report                        # results/report/ に図と表

# 調査用スクリプト
uv run python scripts/score_under_objective.py digits --gammas 1
uv run python scripts/diagnose_outliers.py hier_blobs -m tsne "scalerank:gamma=1.0"
uv run python scripts/force_decomposition.py hier_blobs --epochs 700

定式化と調査の詳細は docs/scalerank.md にあります。
